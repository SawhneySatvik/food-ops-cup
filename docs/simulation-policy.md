# Simulation policy: simulated means labelled

Munim is built to run a real restaurant or shop. This repository runs a demonstration. The rule is that anything that is not
real is said to be not real, in the product, in the data, in the database and in these docs.

## What is simulated

| Thing | Status | How it is labelled and enforced |
|---|---|---|
| Businesses, outlets, people, customers, orders, history | **Synthetic.** Generated by `tools/worldgen`; the demo business is "Cobnut Bakehouse (synthetic)" with addresses marked synthetic. | Every staff screen on a demo business shows "Sample data" (`apps/web/components/staff/shell.tsx`). Demo e-mail addresses use the reserved `.invalid` domain. |
| Suppliers | **Simulated.** Three agents (`steady`, `discounter`, `premium`) in `services/suppliers-sim`, deterministic from `suppliers_sim/personalities.json`. The demo's other suppliers are rows named "(simulated)". | Each agent card's name ends in "(Simulated supplier)". Every supplier screen says so (`apps/web/lib/munim/staff-copy.ts`). intel checks the card before sending anything. `intel.supplier_quote` can reference only a supplier of kind `simulated`, enforced by a foreign key and a check constraint. |
| Community-food recipients (Munim Cares) | **Simulated.** Rows in `platform.cares_recipient`. | Screens say "Simulated recipient". Impact figures always carry "Measured on synthetic data" and "to simulated recipients" (`services/core-api/src/modules/cares-network/index.ts`). |
| Payments | **Recorded, never processed.** A tender is a row that says what a person says was paid. | No payment gateway, card network or bank client exists in the code. Receipts and the till record methods and amounts only. |
| Messages to customers | **Never sent.** A campaign is a draft a person approves. | The customers module is scanned in its tests for any network client, mail or message client, delivery adapter or "sent" status. The one exception is a demo business, where the owner's own command may record a queued campaign as "Sent (simulated)" (`services/core-api/src/modules/customers/campaign-sent.ts`); every other business refuses it with `demo_only`. |
| Regulators | **Never contacted.** | Compliance shows logs and dates; it files nothing and certifies nothing (`not_a_certificate`). |

## What is real

- The code. Orders, prices, taxes, journals, permissions, approvals and audit run exactly as they would for a real business.
- The AI calls. In a live deployment the models are called for real, under a monthly spend limit per business. Their inputs
  are synthetic data.
- Sign-in. The deployed site uses Google Cloud Identity Platform for the four demo people.

## Figures

Any "savings" or "money found" figure Munim shows is measured on synthetic data. It describes what the system found in the
Cobnut world, not what it would find in a real business. The Cares impact figures say so on every response.

## Rules for contributors

1. A new supplier, recipient, customer, channel or payment feature must either be simulated and say so, or not be added.
2. A screen that shows a supplier without "Simulated supplier" is a bug.
3. Nothing is sent to a real person or service on behalf of a business. A feature that would send needs a person's approval
   as a draft, and the draft must say what would be sent and to whom.
4. Synthetic names, addresses and tax identifiers must be marked or use reserved ranges, so none can be mistaken for a real one.
